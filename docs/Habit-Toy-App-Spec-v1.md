## 0. 문서 목적과 기본 가정

이 문서는 Habit Toy 앱과 4버튼 하드웨어를 하나의 제품으로 정의한다. 기획, 디자인, 모바일, 백엔드, 임베디드 개발자가 동일한 사용자 흐름과 상태 규칙을 기준으로 구현하는 것이 목적이다.

### 0.1 기본 가정

- 앱은 스마트폰 세로 화면을 기준으로 설계한다.
- 해커톤에서는 모바일 웹 또는 PWA로 구현할 수 있다.
- 출시 버전은 백그라운드 동기화와 BLE 연결을 지원하는 모바일 앱을 기본으로 한다.
- 기기는 버튼 입력 시각과 이벤트를 로컬에 저장하며, 휴대폰이 없거나 연결이 끊겨도 기록을 잃지 않는다.
- 기기와 앱의 통신 방식은 하드웨어 사양에 따라 BLE 또는 Wi-Fi를 사용할 수 있도록 추상화한다.
- 한 사용자에게 동시에 진행 가능한 Category는 하나다.
- 시간 목표는 선택 사항이다. 목표를 설정하지 않아도 기록할 수 있다.
- AI는 기록을 계산하는 주체가 아니다. 확정된 통계를 사람이 읽기 쉬운 리플렉션으로 설명하는 역할만 한다.

### 0.2 버전 구분

| 표기 | 의미 |
|---|---|
| H0 | 해커톤에서 반드시 구현할 범위 |
| M1 | 첫 출시 MVP에 포함할 범위 |
| M2 | 출시 후 검증을 거쳐 확장할 범위 |

# Part A. 화면설계서

## 1. 정보구조

### 1.1 하단 내비게이션

```text
오늘        기록        리플렉션        설정
```

- `오늘`: Active 4, 현재 타이머, 오늘의 진행 상태
- `기록`: 날짜와 Category별 누적 시간, 세션 상세
- `리플렉션`: AI가 발견한 기록 패턴

해커톤 H0에서는 `오늘`, `기록`, `리플렉션` 3개만 제공하고 설정 기능 일부를 오늘 화면의 메뉴에 넣을 수 있다.

## 2. 공통 UI 원칙

### 2.1 기록 표현

- 시간은 기본적으로 `분` 단위로 표시한다.
- 60분 이상은 `1시간 20분` 형식을 사용한다.
- 1분 미만 기록도 삭제하지 않고 `1분 미만`으로 표시한다.
- 히트맵의 채움 정도는 목표가 있으면 `당일 누적 시간 ÷ 목표 시간`으로 계산한다.
- 목표가 없으면 해당 기간 내 Category의 상대적 사용 시간으로 명암을 계산하되, 범례에 `상대 강도`임을 표시한다.
- 100%를 초과한 시간도 숫자로 보존하고 시각적으로 별도 강조한다.

### 2.2 색상과 접근성

- Category별 색상은 사용자가 선택하거나 자동 배정한다.
- 색상만으로 상태를 구분하지 않고 아이콘, 텍스트, 패턴을 함께 사용한다.
- 진행 중 상태에는 `진행 중` 문구와 애니메이션을 함께 제공한다.
- 모든 주요 터치 영역은 최소 44×44pt를 확보한다.

### 2.3 시간의 기준

- 원본 데이터는 UTC로 저장하고 화면에는 사용자 시간대로 변환한다.
- 자정을 넘긴 세션은 실제 시작·종료 시각을 유지한다.
- 일별 통계에서는 자정 기준으로 시간을 나누어 각 날짜에 배분한다.
- 사용자가 시간대를 변경해도 원본 타임스탬프는 변경하지 않는다.

## 3. 화면별 상세 설계

## S00. 시작 및 복원

### 목적

처음 사용하는 사람은 빠르게 체험을 시작하고, 기존 사용자는 자신의 기록을 복원한다.

### 구성

```text
[Habit Toy 로고]

중요한 시간을
눈앞에 남겨보세요.

[시작하기]
[기존 계정으로 계속]
```

### 동작

- `시작하기`: 게스트 또는 간편 가입 후 S01로 이동한다.
- `기존 계정으로 계속`: 인증 후 서버 데이터를 내려받는다.
- 해커톤 H0에서는 인증 없이 데모 사용자로 바로 시작할 수 있다.

### 상태

- 네트워크 오류
- 계정 복원 중
- 복원할 데이터 없음
- 다른 기기에서 진행 중인 세션 존재

## S01. 제품 소개

### 목적

Habit Toy의 핵심 사용법을 3단계 안에 설명한다.

### 구성

```text
1. 중요한 네 가지를 고르세요.
2. 시작할 때 버튼을 누르세요.
3. 작은 시간도 기록으로 남겨보세요.

[나의 Active 4 만들기]
```

### 원칙

- 권한 요청이나 긴 설명을 먼저 보여주지 않는다.
- 온보딩은 건너뛸 수 있다.
- `AI 코칭`보다 `기록의 간편함`을 먼저 설명한다.

---

## S02. Category 생성

### 목적

사용자가 시간을 쓰고 싶은 삶의 영역을 생성한다.

### 구성

```text
어떤 시간들을 남기고 싶나요?

[운동] [독서] [공부] [창작]
[음악] [프로젝트] [명상] [직접 입력]

선택 4개 이상 가능
[계속]
```

### 입력 항목

| 항목 | 필수 | 규칙 |
|---|---:|---|
| Category 이름 | 필수 | 1~20자, 사용자 내 중복 금지 |
| 색상 | 선택 | 자동 배정 가능 |
| 아이콘 | 선택 | 기본 아이콘 제공 |
| 일일 목표 | 선택 | 5~720분 |

### 동작 및 예외

- 추천 항목을 누르면 즉시 생성된다.
- 같은 이름이 있으면 새로 만들지 않고 기존 Category 선택을 제안한다.
- 최소 1개만 생성해도 계속할 수 있으며, 비어 있는 버튼은 미할당 상태로 둔다.

## S03. Active 4 설정

### 목적

최대 네 개 Category를 실제 버튼 위치와 연결한다.

### 구성

```text
Habit Toy의 네 버튼을 정해주세요.

┌────────┬────────┐
│ 1 운동  │ 2 독서  │
├────────┼────────┤
│ 3 음악  │ 4 프로젝트│
└────────┴────────┘

드래그해서 위치 변경
[기기 연결하기]
```

### 동작

- Category를 드래그하여 버튼 위치를 변경한다.
- 이미 배치된 Category를 다시 선택하면 배치를 해제한다.
- 저장 즉시 `ActiveAssignment` 버전을 증가시킨다.
- 기기에 새 매핑이 동기화되기 전까지 앱에 `동기화 대기` 상태를 표시한다.

### 중요 규칙

- 과거 기록은 Active 4에서 제거해도 유지된다.
- 진행 중인 Category는 배치에서 제거할 수 없다. 먼저 세션을 종료해야 한다.
- 기기가 오프라인이면 앱에는 먼저 저장하고, 연결 시 새 배치를 전송한다.

## S04. 기기 연결

### 목적

Habit Toy를 발견하고, 계정과 연결하고, 네 버튼이 올바르게 작동하는지 확인한다.

### 구성

```text
Habit Toy 연결

기기의 연결 버튼을 3초간 눌러주세요.

[검색 중...]

발견된 기기
Habit Toy A1B2   신호 강함

[연결]
```

연결 후 테스트:

```text
1번 버튼을 눌러보세요.
[●] 입력을 확인했어요.

[설정 완료]
```

### 상태

- 권한 필요
- 검색 중
- 기기 없음
- 다른 계정에 연결된 기기
- 연결 성공
- 매핑 동기화 중
- 펌웨어 호환 불가

### 오류 복구

- 기기를 찾지 못하면 Bluetooth/Wi-Fi와 기기 전원을 확인하도록 안내한다.
- 연결 도중 앱을 닫아도 다음 실행 시 설정을 이어간다.
- 해커톤에서는 연결 대상을 한 대로 고정하고 페어링 과정을 단순화할 수 있다.

## S10. 오늘 홈

### 목적

앱을 열었을 때 현재 진행 상태와 오늘 Active 4에 쓴 시간을 즉시 보여준다.

### 기본 화면

```text
8월 19일 수요일                         [기기 ●]

오늘 남긴 시간
2시간 14분

┌─────────────────┐
│ 운동                         35분 │
│ ███████░░░      목표 60분 │
└─────────────────┘
┌─────────────────┐
│ 독서                         42분 │
│ █████████░      목표 60분 │
└─────────────────┘
┌─────────────────┐
│ 음악                         18분 │
│ ████░░░░░░      목표 45분 │
└─────────────────┘
┌─────────────────┐
│ 프로젝트                     39분 │
│ ██████░░░░      목표 90분 │
└─────────────────┘

[앱에서 직접 기록]
```

### 진행 중 상태

```text
독서 진행 중
00:18:32

[종료]
```

해당 Category 카드는 상단으로 이동하고 명확한 진행 애니메이션을 표시한다.

### 동작

- Category 카드 선택: S23 Category 상세로 이동한다.
- 진행 중 카드 선택: S11로 이동한다.
- `앱에서 직접 기록`: Category를 선택해 하드웨어 없이 타이머를 시작한다.
- 기기 아이콘 선택: S42로 이동한다.
- 아래로 당겨 새로고침하면 기기와 서버 동기화를 재시도한다.

### 상태

- 오늘 기록 없음: `첫 버튼을 눌러 오늘의 시간을 남겨보세요.`
- 진행 중
- 기기 오프라인, 로컬 기록 존재
- 동기화 중
- 동기화 실패
- Active 4 미설정

## S11. 진행 중 세션

### 목적

현재 활동과 경과 시간을 확인하고 종료하거나 잘못 시작한 기록을 취소한다.

### 구성

```text
독서

00:18:32
21:04 시작

[종료하고 저장]
[잘못 시작했어요]
```

### 동작

- 종료: 현재 시각으로 Session을 종료하고 S12로 이동한다.
- 잘못 시작: 확인 후 세션을 삭제하지 않고 `discarded` 상태로 보존한다.
- 앱이 백그라운드에 있어도 서버 또는 타임스탬프 기준으로 경과 시간을 계산한다.

### 예외

- 기기에서 먼저 종료된 경우 화면을 자동 갱신한다.
- 앱과 기기 양쪽에서 동시에 종료 이벤트가 발생하면 최초 유효 이벤트 하나만 적용한다.
- 12시간 이상 진행 시 사용자에게 확인 알림을 보낸다. 자동 종료는 하지 않는다.

## S12. 기록 완료

### 목적

저장 성공을 확인시키고, 원하는 사용자만 기록에 추가 맥락을 붙인다.

### H0 구성

```text
기록했어요.

독서
21:04–21:36 · 32분

[완료]
```

### M1 확장

```text
무엇을 했나요?             선택 사항
[소설] [전공서] [+ Session]

한 줄 메모                 선택 사항
[_______________________]

[저장]
```

### 원칙

- 종료와 동시에 시간 기록은 이미 저장되어 있어야 한다.
- 추가 정보를 입력하지 않고 화면을 닫아도 기록은 유지된다.
- 사진 첨부는 M2로 분리한다.

## S20. 기록 캘린더

### 목적

작은 실천이 시간에 따라 어떻게 쌓였는지 보여준다.

### H0 구성

```text
기록                                  [최근 7일]

        목  금  토  일  월  화  수
운동    ▱  ■  □  ▰  ▱  □  ▰
독서    ■  ▱  ▰  ■  □  ▱  ▰
음악    □  ▱  □  ▰  ■  ▱  ▱
프로젝트 ▰  ■  ▱  □  ▰  ■  ▰

이번 주 총 9시간 42분
```

### M1 확장

- 기간: 7일 / 30일 / 분기 / 1년
- Category 필터: 전체 / 개별 Category
- 날짜 선택: S21로 이동
- 범례: 없음 / 조금 / 목표 근접 / 목표 달성 / 초과

### 표시 규칙

- 기록이 1초라도 있으면 빈 칸과 다른 상태를 표시한다.
- 동기화되지 않은 데이터는 점선 테두리로 표시한다.
- 목표 변경 시 과거의 채움 정도는 해당 날짜에 적용되던 목표를 기준으로 유지한다.

## S21. 날짜 상세

### 목적

특정 날짜에 무엇을 언제, 얼마나 했는지 확인한다.

### 구성


## S30. 리플렉션 피드

### 목적

사용자의 기록에서 발견된 의미 있는 변화와 패턴을 평가 없이 전달한다.

### 구성

```text
리플렉션

이번 주
독서는 밤 9시 이후 시작했을 때
평균 18분 더 오래 이어졌습니다.

근거: 최근 4주 · 독서 기록 12개
[자세히]
```

### 상태

- 데이터 충분: 최대 3개의 리플렉션 표시
- 데이터 부족: `기록이 조금 더 쌓이면 패턴을 알려드릴게요.`
- 생성 실패: 기존 리플렉션을 유지하고 재시도
- 사용자가 숨긴 리플렉션: 동일 메시지를 일정 기간 재생성하지 않음

### 피드백

- `도움이 됐어요`
- `지금은 필요 없어요`
- `이런 리플렉션 숨기기`

좋아요 수를 공개하거나 사용자의 성취 점수로 사용하지 않는다.

### 7.1 버튼 이벤트 처리 규칙

기기는 최소한 다음 값을 가진 이벤트를 생성한다.

```json
{
  "eventId": "uuid",
  "deviceId": "device-id",
  "buttonIndex": 1,
  "pressedAt": "2026-08-19T12:04:22Z",
  "mappingVersion": 7,
  "sequence": 184
}
```

서버 또는 앱은 `eventId`를 기준으로 중복을 제거한다. `sequence`가 건너뛰면 누락 이벤트를 다시 요청한다.

### 7.2 세션 상태 머신

```text
IDLE
 └─ BUTTON_A → RUNNING(A)

RUNNING(A)
 ├─ BUTTON_A → COMPLETED(A) → IDLE
 └─ BUTTON_B → COMPLETED(A) + RUNNING(B)
```

추가 상태:

- `PENDING_SYNC`: 기기에 있으나 앱·서버에 아직 반영되지 않은 이벤트
- `DISCARDED`: 사용자가 잘못된 시작으로 표시한 기록
- `DELETED`: 복구 기간 중인 기록
- `CONFLICT`: 자동 해결할 수 없는 시간 충돌

### 9.1 AI 입력

- 익명화된 Category 식별자 또는 사용자가 허용한 Category 이름
- 기간별 총시간
- 활동일 수
- 세션 수와 평균·중앙 지속 시간

- 통계 산출에 사용된 표본 수

### 9.2 AI 출력 스키마

```json
{
  "type": "time_of_day_pattern",
  "categoryId": "reading-id",
  "message": "독서는 밤 9시 이후 시작했을 때 평균 18분 더 오래 이어졌습니다.",
  "evidence": {
    "periodStart": "2026-07-23",
    "periodEnd": "2026-08-19",
    "sampleCount": 12,
    "values": [43, 25],
    "unit": "minutes"
  },
  "confidence": "medium"
}
```

### 9.3 AI 생성 금지 사항

- 제공되지 않은 수치나 원인 추정
- 사용자의 성격, 건강, 생산성에 대한 진단
- `게으르다`, `실패했다`, `반드시 해야 한다`와 같은 평가적 표현
- 데이터가 적은 상태에서 확정적인 패턴 제시

# Part C. PRD

## 12. 제품 개요

### 12.1 제품명

Habit Toy

### 12.2 제품 정의

Habit Toy는 사용자가 중요하게 생각하는 최대 네 개의 삶의 영역을 물리 버튼에 연결해 활동 시간을 기록하고, 누적된 시간을 빛·앱 시각화·AI 리플렉션으로 되돌려주는 개인 시간 기록 제품이다.

### 12.3 핵심 가치 제안

> 앱을 열지 않고 버튼만 눌러 중요한 시간을 기록한다. 목표를 완벽하게 채우지 못해도 실제로 사용한 시간은 사라지지 않는다.

---

## 13. 배경과 문제 정의

기존 습관 앱은 사용자가 행동을 시작할 때 스마트폰을 열고 타이머나 체크리스트를 조작하도록 요구한다. 집중하려는 행동과 기록 도구가 서로 충돌하며, 기록 누락이 데이터의 신뢰도를 떨어뜨린다.

또한 완료 중심 인터페이스는 부분적인 실천을 실패처럼 보이게 한다. 사용자는 자신이 실제로 사용한 시간보다 목표를 달성했는지만 보게 된다.

Habit Toy는 기록 입력을 물리 버튼으로 이동시키고, 결과를 연속적인 시간 데이터로 표현해 이 문제를 해결한다.

## 14. 목표 사용자

### 14.1 1차 사용자

휴대폰 사용을 줄이면서 운동, 독서, 공부, 창작, 개인 프로젝트 등의 시간을 기록하고 싶은 학생·직장인·창작자.

### 14.2 Job To Be Done

### 14.3 비타깃

- 할 일과 마감일을 복잡하게 관리하려는 사용자
- 팀원의 근무 시간을 감시하려는 조직

- 초 단위 과금이나 법적 증빙이 필요한 시간 추적 사용자

## 17. 핵심 사용자 시나리오

### 시나리오 A. 첫 설정

1. 사용자는 앱에서 운동, 독서, 음악, 프로젝트를 만든다.
2. 네 Category를 버튼 1~4에 배치한다.
3. 기기를 연결하고 버튼 테스트를 완료한다.
4. 기기의 네 버튼이 Category 색상으로 짧게 점등된다.

### 시나리오 B. 앱을 열지 않고 기록

1. 사용자는 독서를 시작하며 2번 버튼을 누른다.
2. 독서 버튼이 천천히 점멸한다.
3. 32분 후 같은 버튼을 다시 누른다.
4. 기기는 종료를 표시하고 이벤트를 저장한다.
5. 앱을 나중에 열면 독서 32분이 오늘 기록과 히트맵에 반영되어 있다.

### 시나리오 C. 활동 전환

1. 운동 기록이 진행 중이다.
2. 사용자가 프로젝트 버튼을 누른다.
3. 운동은 해당 시각에 종료되고 프로젝트가 시작된다.
4. 두 기록 모두 중복 없이 저장된다.

### 시나리오 D. 연결 없는 기록

1. 휴대폰이 근처에 없는 상태에서 버튼을 누른다.
2. 기기가 이벤트를 로컬에 저장하고 정상적으로 LED를 표시한다.
3. 이후 앱과 연결되면 이벤트가 순서대로 동기화된다.
4. 앱의 통계가 자동으로 갱신된다.

### 시나리오 E. AI 리플렉션

1. 사용자의 독서 기록이 기준 이상 축적된다.
2. 서버가 시간대별 평균 지속 시간 차이를 계산한다.
3. AI가 제공된 숫자만 사용해 한 문장을 생성한다.
4. 사용자는 문장과 함께 기간, 표본 수, 비교값을 확인한다.

| Active 4 오프라인 변경 | 이벤트의 mappingVersion으로 Category 결정 |
| AI API 오류 | 기록 기능 정상 유지, 리플렉션만 재시도 |
| AI 근거 불일치 | 출력 폐기, 템플릿 기반 문장으로 대체 |

## 24. 해커톤 구현 순서

### 1단계: 하드웨어 상태 머신

- 버튼 입력
- 시작·종료·전환
- 진행 LED
- 시리얼 로그 또는 네트워크 이벤트 전송

### 2단계: 앱 핵심 화면

- 오늘 홈
- 진행 중 타이머
- 7일 히트맵
- 리플렉션 카드

### 3단계: 종단 간 연결

- 실제 버튼 이벤트가 앱 상태를 변경
- 세션 종료 후 오늘 누적과 히트맵 갱신
- 중복 이벤트 방지

### 4단계: AI 리플렉션

- 예시 과거 데이터에서 통계 후보 계산
- 구조화된 AI 출력 생성
- 근거값과 함께 화면 표시

### 5단계: 데모 안정화

- 연결이 끊겨도 버튼과 앱을 각각 복구
- 데모 데이터 초기화 기능
- 실제 기록과 예시 기록 표시
- 3분 발표 시나리오 반복 테스트

## 26. 출시 게이트

다음 조건을 모두 충족해야 정식 출시 후보로 판단한다.

- 2주 이상 사용하는 베타 사용자에게서 치명적 기록 유실이 없다.
- 1,000회 이상의 버튼 테스트에서 이벤트 성공률 99.9% 이상이다.
- 오프라인 시작·종료·재연결 시나리오가 반복 재현된다.
- 앱과 기기의 진행 상태 충돌을 사용자가 해결할 수 있다.
- 계정 삭제 및 데이터 내보내기가 정상 작동한다.
- AI 문장과 근거 데이터의 일치 여부를 자동 검증한다.
- AI 기능을 꺼도 모든 핵심 기록 기능이 정상 작동한다.
- 최소 35%의 베타 사용자가 2주차에도 주 3일 이상 기록한다.

## 27. 미결정 사항

구현 전 또는 베타에서 결정해야 할 항목이다.

1. 출시 하드웨어의 주 통신 방식: BLE 단독 또는 Wi-Fi 병행
2. 기기 내 RTC와 로컬 이벤트 저장 용량
3. 버튼 형태: 개별 키캡, 로터리 포함, 전자종이 라벨 여부
4. 하나의 계정에 여러 Habit Toy를 허용할 시점
5. 목표가 없는 Category의 장기 히트맵 명암 계산 방식
6. 매우 짧은 오입력 기록을 자동 폐기할지 여부
7. AI 리플렉션 생성 빈도와 비용 상한
8. 하드웨어 판매가와 AI 구독의 분리 방식

## 28. 최종 제품 문장

> Habit Toy는 목표를 완벽하게 지켰는지 평가하는 습관 앱이 아니다. 앱을 열지 않고도 중요한 활동의 시작과 끝을 기록하고, 실제로 사용한 작은 시간들이 어떻게 삶의 방향으로 쌓이고 있는지 보여주는 개인 기록 도구다.
